# ADR 0001: 会话阅读模式现代化改造 (Session Reader Modernization)

* **状态 (Status)**: 已接受 (Accepted)
* **日期 (Date)**: 2026-10-12
* **领域 (Domain)**: 会话阅读 (Session Reading) / 实时流 (Real-time Streaming) / 移动端呈现 (Mobile UX)
* **关联 (Related)**: [ADR 0002: 会话列表信息架构与多维组织](0002-session-list-information-architecture.md)

---

## 1. 背景与上下文 (Context)

PalmDesk 作为定位面向 **AI-native remote control** 与 **agent-ready workflows** 的远程操作工具，其“会话阅读”模块扮演着用户不依赖屏幕截图、以纯文本/结构化方式快速追踪 Agent 执行进度的核心角色。

然而，当前阅读模式存在以下体验痛点：
1. **数据同步延迟高**：手机端依靠 8 秒固定周期的客户端短轮询（`setInterval(..., 8000)`）。新消息到达后不自动更新视图，必须由用户手动点击浮动提示条，缺乏实时推流体验。
2. **格式渲染粗糙**：使用简陋的手写正则 Markdown 解析器，缺失代码语法高亮与一键复制代码功能；命令执行与工具输出全量堆叠在灰底 `<details>` 中；且底层主动过滤了关键的 Agent 思考过程（Thinking / Chain-of-Thought）。
3. **状态展示粗放滞后**：仅支持「正在执行 / 本轮已结束 / 状态未知」三种静态文字，且无法感知 Agent 正在执行哪条具体命令、是在推理还是在等待用户交互。

---

## 2. 决策记录 (Decisions)

经技术方案评审与产品交互对齐，决定进行如下架构改造：

### 2.1 实时数据同步与推送架构
* **废弃 8 秒短轮询**：主机端针对当前查看的单一会话日志文件挂载增量文件监听（基于文件偏移量 `offset` 的 Tail Watcher）。
* **WebRTC DataChannel 主动推流**：在原有的独立可靠 DataChannel（`SessionReader`）上扩展协议，新增 `watch` 与 `unwatch` 请求，主机在日志追加新行时增量解析并主动向客户端发送 `push` 帧（携带增量 blocks、patch 与细粒度状态）。
* **零入侵安全边界**：继续保持无特权、纯只读的文件流读取，不调用 Agent CLI、不注入终端进程。

### 2.2 现代化 Agent 对话流与格式渲染
* **技术选型**：引入成熟轻量的 `markdown-it` 与 `highlight.js`（按需引入主流语言包），支持完整的 GFM 语法（表格、任务列表、引用）、代码语法高亮与右上角一键复制。
* **专用卡片设计**：
  * **Bash 终端卡片**：提供深色控制台质感外观，带有命令行 `$` 前缀与输出折叠限制；
  * **Diff 差异卡片**：文件变动提供清晰的 `+ / -` 行数与差异红绿高亮；
  * **Thinking（思考过程）卡片**：在底层适配器中解禁并解析模型的 `thinking` 块，前端呈现为可折叠抽屉，保留思维脉络同时避免侵占首屏。

### 2.3 细粒度状态反馈
* **状态模型细化**：细化为 `thinking`（思考中）、`executing_tool`（运行工具及具体命令）、`waiting_user`（等待用户确认/输入）与 `idle`（本轮完成）。
* **动态状态栏**：时间线底部常驻轻量动态状态栏，伴随优雅的呼吸灯动画，完成时平滑淡出过渡。

### 2.4 智能贴底视窗滚动 (Smart Stick-to-Bottom)
* **自动跟随**：当用户视窗处于最底部时，推流到达时自动平滑吸底滚动，确保最新内容实时可见；
* **防打扰定格**：当用户手指上滑翻阅历史记录时，立即锁定滚动位置，右下角弹出悬浮「最新消息 ↓」按钮，点击一键回到底部。

### 2.5 交互协同边界
* 保持阅读模式的只读与轻量，遇到需要人工输入、确认或执行的场景，通过「继续 ↗」快捷按钮无缝切入对应的桌面 GUI 窗口操作。

## 3. 影响与收益 (Consequences)

### 正向影响 (Positive)
* **流畅度质变**：从 8 秒滞后提升至亚秒级实时推流，真正实现现代 AI Agent 的打字机式流式感知体验。
* **可读性飞跃**：代码高亮、终端命令卡片、Diff 卡片和思考过程折叠，大幅降低移动端查阅复杂代码和终端输出的认知负担。
* **状态透明度**：直观掌握 Agent 的真实执行阶段，减少用户“卡死与否”的疑虑。
* **平滑回退与安全性**：保持原有只读安全边界与窗口切回机制，不破坏现有 WebRTC 输入通道的低延迟特性。

### 代价与权衡 (Trade-offs & Mitigations)
* **打包体积增加**：引入 `markdown-it` 和 `highlight.js`。通过按需加载常用编程语言包（TS/JS/Python/Bash/JSON/HTML/CSS 等），将增量体积严格控制在移动端极速加载范畴内。
* **主机监听资源**：针对且仅针对当前打开的活跃文件进行监听（单会话），切换或关闭时立即 dispose，杜绝多文件常驻与内存泄漏风险。
