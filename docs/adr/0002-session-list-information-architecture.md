# ADR 0002: 会话列表信息架构与多维组织 (Session List Information Architecture)

* **状态 (Status)**: 已接受 (Accepted)
* **日期 (Date)**: 2026-10-12
* **领域 (Domain)**: 会话阅读 (Session Reading) / 列表信息架构 (Information Architecture) / 移动端呈现 (Mobile UX)
* **关联 (Related)**: [ADR 0001: 会话阅读模式现代化改造](0001-session-reader-modernization.md)

---

## 1. 背景与上下文 (Context)

在 [ADR 0001](0001-session-reader-modernization.md) 中，PalmDesk 确立了会话详情页的主动推流架构、高质量 Markdown 渲染、思考过程折叠和只读安全边界。然而，当用户进入阅读模式主页寻找目标会话时，遇到了显著的信息散乱与定位困难：

1. **扁平列表缺乏时间感知**：所有会话按更新时间简单平铺，没有「今天」、「昨天」、「本周」等时间断点，用户在长列表中需要逐条阅读微缩时间文本才能辨别时间跨度。
2. **多工程/仓库混杂**：现代开发者常跨多个项目工作，各项目的会话卡片混杂在一起，找特定项目的历史必须肉眼扫视。
3. **进行中任务淹没**：正在运行中（Running / Thinking）或等待用户交互（Waiting for input）的高优会话缺乏视觉突出与专属入口，容易被历史会话冲淡。
4. **筛选门槛过高**：原本唯一的过滤手段是敲键盘输入文字并点击「搜索」按钮，在移动端输入成本高，缺乏 0 键盘输入的点选式快速筛选。

---

## 2. 决策记录 (Decisions)

为打造真正符合 AI-native 与 agent-ready 定位的高效检索体验，决定对会话列表的信息架构与交互做出如下重构：

### 2.1 时间分段智能流 (Timeline Partitioning)
* 将拉取的会话列表根据 `lastUpdatedAt` 自动划分为四个自然时间段：
  * **今天 (Today)**：当天 00:00 之后更新的会话；
  * **昨天 (Yesterday)**：昨天全天更新的会话；
  * **近 7 天 (Last 7 Days)**：前天起至 7 天前的会话；
  * **更早 (Earlier)**：7 天以前的历史归档。
* **空分组自适应折叠**：若某一时间段在当前筛选条件下无记录，自动隐藏该时间分组，避免视觉冗余。

### 2.2 粘性吸顶分组标题 (Sticky Section Headers)
* 各时间段头部采用粘性吸顶（`position: sticky; top: 0`）排版，带有半透明毛玻璃背景（`backdrop-filter: blur(8px)`）。
* 用户在竖向滑动浏览长列表时，当前所在时间段标题自然驻留在顶部，时刻提供清晰的上下文锚点。

### 2.3 横向滚动 Chip 胶囊筛选栏 (Horizontal Filter Chips)
* 在搜索框下方提供单行横向滑动的渐进式胶囊 Chip 标签栏，按「全局状态 → Agent 类别 → 视觉分隔线 → 具体工程项目」层级顺序组织：
  * **前置全局与状态标签**：
    * `全部 (All)`：展示所有匹配会话；
    * `🟢 运行中 (Running)`：一键过滤出所有正在执行、思考或调用工具的活跃 Agent 任务；
  * **动态 Agent 来源分类**：从已加载会话中动态提取电脑中实际存在的 Agent 工具来源（如 `🤖 Claude Code`、`⚡ Codex`、`💻 Claude Desktop`），展示对应会话计数，点击 0ms 瞬间只查看该 Agent 的记录；
  * **视觉分隔线**：在 Agent 来源大类与具体工程标签之间增加轻量竖分隔线（`|`），大类到工程项目层级一目了然；
  * **动态项目分类**：自动聚合高频项目仓库名称（如 `📁 palmdesk` 等），点击即时按工程筛选。
* **即时反馈**：轻触 Chip 触发 0ms 纯前端响应式重排，无需网络往返等待。

### 2.4 结构化卡片排版 (Structured Session Card)
重塑单张会话卡片的视觉层次，分为三层明确重心：
* **顶栏 (Header)**：左侧为浅色底色高亮的项目名称徽章（Project Badge）与相对时间，右侧为醒目的状态指示（运行中显示呼吸动效绿点 `🟢 正在执行`，等待确认显示黄色徽标，已完成显示沉稳灰调）；
* **中栏 (Body)**：加粗会话主标题（突出两行优雅截断，提供最佳视觉焦点）；
* **底栏 (Footer)**：最新一条消息或执行摘要预览（单行截断灰字），右侧带专属品牌色调的 Agent 来源徽标（如 Claude Code 暖调紫、Codex 翠绿蓝，强化快速扫视辨识度）。

### 2.5 混合即时过滤与深度检索机制 (Hybrid Filtering & Deep Search)
* **前端即时过滤 (Local 0ms)**：用户在搜索框中键入字符时，实时在已加载的会话列表中对项目、标题、最新内容进行快速匹配；搜索框提供一键清空 `(×)` 按钮。
* **深度远端检索 (Remote Deep Query)**：当用户按 Enter 键或主动点击「搜索」按钮时，向远端发起请求，穿透本地缓存查询服务端存储的更早历史全量数据。

## 3. 影响与收益 (Consequences)

### 正向影响 (Positive)
* **查找效率质变**：通过横向项目 Chip + 运行中状态 + 时间分段，用户 1 秒内即可定位到「刚才在跑的任务」或「昨天修改过的工程会话」。
* **视觉重心分明**：卡片排版从原先的文字堆砌转变为“工程-状态-标题-摘要”清晰结构，大幅降低移动端扫视负担。
* **零性能开销**：分组与前端过滤基于内存中现有 100 条会话进行，计算耗时 < 1ms，滚动与交互 60fps 丝滑流畅。

### 权衡 (Trade-offs)
* 手机横向屏幕空间有限，Chip 标签栏需支持横向手势惯性滑动（`-webkit-overflow-scrolling: touch`）并隐藏滚动条。
